### Resolutions

- **`jspdf` critical (LFI + PDF Injection + 8 other CVEs)** → upgraded `packages/frontend/package.json` from `^3.0.3` → `^4.2.1` (semver-major). API surface used by `utils/markdownProcessor.ts` (`new jsPDF()`, `pdf.text`, `setFontSize`, `setFont`, `splitTextToSize`, `addPage`, `internal.pageSize`) is unchanged between v3 and v4 — verified by `npm run build` + `npm test` (95 / 95 pass) + `npm run sbom:generate` re-audit showing 0 criticals.
- **`uuid` moderate (buffer bounds-check, advisory `<11.1.1`)** + **`exceljs` moderate (transitive via uuid)** → both resolved with a single npm `overrides` block at the workspace root:
  ```json
  "overrides": { "uuid": "^11.1.1" }
  ```
  Without the override, `exceljs@4.4.0` pins `uuid@8.3.2` transitively (verified via `npm ls uuid`); with the override, the same `exceljs@4.4.0` now resolves `uuid@11.1.1` (verified via `npm ls uuid` after `rm -rf node_modules + npm install`). `parseExcel.ts` uses `ExcelJS.Workbook` which doesn't touch uuid directly, so this is a transitive-only fix — no Vue code changed. **Note:** removing this override before exceljs releases a version that ships a fixed uuid would regress the audit; the override block in `package.json` carries an inline comment explaining why.
